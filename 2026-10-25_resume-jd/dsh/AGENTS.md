# 这个文件夹的规矩（给 DSH 看的）

这是「原简历 + 多份 JD → 对口版简历 + 待补清单」的工作区。

- 原简历、原 JD 正文不改不删；可归到 raw/。
- 先写「已确认经历清单.md」（公司 / 时段 / 职责与成果原句）。改写只能基于它；禁止编造公司、职位、项目、数据、证书。
- 每份 JD：抽硬性要求与加分项；在 match/ 写匹配说明（已覆盖 / 可改写对齐 / 缺口）。
- 每份 JD 一份对口版到 tailored/（文件名含公司与岗位），只调顺序、小标题、表述；每条能回溯到清单原句。
- JD 要但原简历没有的，写进 gaps/待补清单.md，附一句可执行补法；不写进对口版。
- 不自动投递，不打开招聘网站，不点「立即沟通」「投递」。
- 不确定的标「待确认」，不猜。
- 完成后先展示各岗匹配摘要 + 待补清单，再给对口版路径。
- 产出文件（报告、摘要、清单、简历等）新建用 write 工具，改用 edit 工具；不要用 bash 的 cat/echo/heredoc/python 写产出文件。搬文件、建目录可以用 bash。
- 原件用 `mv` 归进 `raw/`，不改名，根目录不留副本（干完根目录只剩 `AGENTS.md`、`已确认经历清单.md` 和四个子目录）。
- `match/`、`tailored/` 每岗只一份，不另写总览/汇总文件；总览直接在对话里展示。
